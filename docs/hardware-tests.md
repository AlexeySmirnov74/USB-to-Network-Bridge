The 1080p failure occurs with both server modules. Native receives non-empty isochronous responses, but the Windows capture APIs did not deliver frames at that format. A cause has not been established. A related upstream report describes high-resolution issues on some USB 2 cameras: [usbipd-win issue 1006](https://github.com/dorssel/usbipd-win/issues/1006); it is context, not proof of the cause on this fixture.

Driver installation requested a client restart; it was performed manually before these measurements. Neither the Rust module nor the stock module has demonstrated a measured advantage over the other yet. Additional device classes should be recorded as separate rows as they are tested.
